# UI swap: real scores on the dashboard and in Steven's charts

Status: specified 2026-09-13; revised the same day after review.

The dashboard and Steven's `chart` tool have drawn invented, schema-shaped data since before ingest
existed, and every surface said so. Scoring now writes real v2 snapshots — Momentum, Valuation and
Quality — so this replaces the fiction with the real screen, and makes the project's hard constraint
visible where a person looks: **every score traces back to visible raw inputs**, one click from the
row. Standing decisions live in `DESIGN.md`; the tables read are specified in
`docs/specs/2026-09-05-scoring.md` and `docs/specs/2026-09-13-ratios.md`.

Scope: **an explaining form of the scoring functions, two read endpoints over a shared read module, the
Overview page, a traceability panel, a price mode for the one chart renderer, Steven's chart tool, and
the deletion of `screener.concept` and `web/lib/data.ts`.** Nothing is ingested, what scoring computes
and writes does not change, no schema changes, and no alert is evaluated. It ships as three pieces
(§12).

---

## 1. What this has to satisfy

1. **Nothing on screen is invented.** A figure either comes from a table or is not drawn. Features that
   have no data yet are absent rather than mocked.
2. **Every score traces to its inputs on the page.** Selecting a security shows each metric's raw value,
   percentile, peer group and count, and the period it was computed on; a metric that applies but could
   not be computed says why.
3. **A partial score cannot pass for a complete one.** The real screen has partial scores near the top
   (F9).
4. **The screen and Steven cannot disagree.** One definition of the screen's queries and shaping, read
   by both.
5. **Honest about time.** v2 history begins with its first production night; v1 nights are not
   comparable and carry distorted momentum.
6. **What scoring writes is provably unchanged** by making it explain itself.

---

## 2. Findings

**F1 — what the concept UI draws.** The Overview is a client component importing twelve invented rows
from `web/lib/data.ts` at build time: a header ("run #412 … weights v3-momentum-heavy"), four stat
tiles, a table (score, Δ1d, pillars V/Q/M/S/I, agreement, flags, 30-day sparkline), a "blended score,
60d" chart built from a seeded random walk, an alert feed, a provenance footer, and a banner saying
ingest does not exist. `screener.concept` mirrors the rows in Python for Steven's `chart` tool, and
nearly every test in `tests/test_charts.py` imports it.

**F2 — a third of it has no data behind it.** Sentiment and Insider pillars, event flags, alerts and
threshold crossings describe systems that do not exist.

**F3 — there is no data path.** The page has never fetched a score. Other pages read through the status
service behind the GitHub session (`/api/audit` at `screener.health.server`); the web container holds
no database credentials.

**F4 — the real screen is ~1,500 rows.** A 30-close sparkline on every row is ~45,000 points per load.

**F5 — score history is days old.** v2's first production night is 2026-09-13. The four v1 nights
(09-09 to 09-12) scored Momentum alone with split-distorted momentum (scoring spec D4 erratum).

**F6 — the fiction is load-bearing elsewhere.** Steven's system prompt calls chart figures illustrative
sample data and offers "a crossing" as a mark (`src/screener/bot/agent.py`); the Overview publishes
`illustrative = true` into the palette context (`web/lib/screen-context.tsx`); the Steven page carries a
notice; `.concept-bar` styles the banner.

**F7 — nothing records why a metric is absent.** `metric_daily` holds only computed metrics.

**F8 — the web app has no test runner, and lint is not enforced.** `package.json` has `eslint` only; no
workflow runs it, and `next build` in Next 16 does not lint. CI's web image build does typecheck.

**F9 — partial scores rank high.** On a copy of production scored under v2 with the split fix, GEF
ranked fifth with `min_coverage = 0`.

**F10 — Steven's read-only role can read everything needed.** Migration 017 grants `playground_bot`
`select` on the identity, scoring-configuration, fact and derived tables, including `security`,
`security_symbol`, `security_sector`, `sector_node`, `peer_group`, `scoring_run`,
`scoring_logic_version`, `weight_version`, `pillar_weight`, `snapshot_daily`, `pillar_score_daily`,
`metric_daily`, `peer_group_stat`, `metric`, `pillar`, `price_daily`, `fundamental_fact` and
`corporate_action`.

**F11 — the one chart renderer can only draw a score.** `web/lib/chart-svg.ts` fixes the y-domain to
include 20–85, draws gridlines at 25/50/75, always draws a `threshold` and a `median` line, and labels
values with `toFixed(0)`; `ChartSpec` requires `median` and `threshold` (`web/lib/threads.ts`), and
`ChatChart.tsx`'s hover text speaks of a score and an alert threshold. A price series would be squashed
and mislabelled.

**F12 — `playground.select` returns JSON-safe cells, not native types.** `_cell` in
`screener.playground.engine` turns `Decimal` into `str`, `date`/`datetime` into ISO strings and
`timedelta` into `str`, and each `select` opens its own connection with a superuser check. The status
service's own connection returns native types. Shaping code cannot take rows from both unchanged.

**F13 — ingest rewrites the last week of bars every night.** `upsert_unsettled_bars` sets
`observed_at = now()` on the settling window (price-ingest D5). Any read of `price_daily` under a
scoring run's cutoff loses those bars from the moment the next ingest runs until the next scoring run
lands — which a retried, gated or failed night stretches to a day or more.

**F14 — a run saw less than its cutoff allows.** `visibility_cutoff` is `as_of 00:00 UTC + 30h`, but
the nightly run starts at about 23:00 on `as_of`. A manual ingest between the run and its cutoff writes
bars and facts the run never saw but a cutoff-bounded read would.

**F15 — two scoring inputs are not point-in-time.** `read_currencies` reads today's `security.currency`,
and a `security_sector` reclassification loaded after the run but with `valid_from <= as_of` changes
what `resolve` returns for that date.

## 3. Decisions

### What the UI shows

**D1 — Swap plus traceability, and the concept is deleted.** The Overview and Steven's chart move to
real data and a traceability panel is added. `src/screener/concept/`, `web/lib/data.ts`,
`web/components/AlertFeed.tsx` and `.concept-bar` are deleted; `tests/test_charts.py` is rewritten
rather than trimmed, since nearly all of it reads the concept (F1).

**D2 — Price now, score later.** The chart, the sparkline and Steven's tool draw adjusted closes: 60
trading days for the chart and Steven, 30 for the sparkline. A score-history chart is a later cycle
(F5). Steven's marks become `peak`, `low`, `surge`, `drop`, `latest`; `crossing` is removed until score
history and alerting exist.

**D3 — Remove until built.** S and I columns, flags, the alert feed and the crossings tile are removed;
each returns with the cycle that builds its data. Partial scores stay in the default view, marked, rather
than hidden or sorted last: hiding them would silently narrow the screen by ~40 securities, and the
filter and the tile make excluding them one click.

**D4 — Layout A, panel as a grid.** Table on the left; the right column holds the price chart above the
"Why this score" panel. The panel is a compact grid per pillar: metric (↓ when lower is better), value,
percentile bar, peers, period.

**D5 — Units and precision.**

| metrics | shown as |
|---|---|
| `earnings_yield`, `ebitda_ev`, `fcf_yield`, `ffo_yield`, `roic`, `roe`, `gross_margin`, `ret_3m`, `ret_6m`, `ret_12m`, `off_52w_high` | percent, one decimal |
| `book_yield`, `debt_to_equity`, `interest_cover` | multiple, two decimals, `×` |
| percentiles | integer 0–100 |
| blended and pillar scores | one decimal |
| closes | two decimals below 1,000, none at or above |

Payloads carry metric values and reproduced values as **exact decimal strings**, never floats, so a
mismatch is never two identical-looking rounded numbers; the panel shows both and their difference.

### The data path

**D6 — Read endpoints on the status service, over one module that owns its row types.**
`GET /api/screen` and `GET /api/screen/security` live in `screener.health.server` behind the session, as
`/api/audit` does, on the application's own connection: the SQL is fixed and only bound parameters vary,
which is what the playground's read-only role exists to guard against (it protects SQL a person types).
The package `screener.screen` holds:

- `queries.py` — SQL literals only.
- `rows.py` — typed row records and the **parsing that turns either source into them**: native values
  from a psycopg cursor, or `playground.Result` cells (decimal strings, ISO dates) back to `Decimal`,
  `date` and `datetime` (F12). Shaping and adjustment only ever see typed rows.
- `shape.py` — pure: typed rows into the D9/D10 JSON.
- `explain.py` — reproduction (D12–D14).

Steven uses the same `queries.py` and `rows.py` through `playground.select`, in at most three queries
per chart (D17).

Rejected: the whole screen in one response filtered in the browser; a nightly JSON artifact; database
credentials in the web container; browser-side SQL through the playground API.

**D7 — Which night.** The screen's run is the latest `scoring_run` with `status = 'live'`,
`outcome = 'ok'`, `logic_version_id` equal to the one row whose `description` is
`screener.scoring.run.LOGIC_DESCRIPTION`, ordered by `lower(as_of_range)` then `id`. Its **previous**
night, for Δ, is the latest such run with an earlier `lower(as_of_range)` **and the same
`weight_version_id`**; a weight change starts Δ afresh. With no qualifying run, both endpoints return
`{"state": "awaiting_first_night"}` and the page says the first v2 night has not been scored yet — no
time is promised, because the status service does not hold the scheduler's configuration.

**D8 — Pinned to one run while browsing.** Every response carries `run.id`; both endpoints accept
`run=<id>`. A pinned run is served while it still qualifies under D7 apart from being latest, with
`"latest": false`, and the page shows "a newer night is available" with a refresh action. An unknown or
non-qualifying id is 409 `run_changed`. Every sort order ends with `security_id`, so pages never overlap
or skip on ties.

**D9 — `GET /api/screen`.**

| parameter | values | default |
|---|---|---|
| `run` | a run id | the screen's run |
| `sector` | a level-1 sector code, or `unclassified` | all |
| `agree` | `1`, `2`, `3` — minimum pillar agreement | none |
| `partial` | `only`, `hide` | both |
| `sort` | `score`, `delta`, `V`, `Q`, `M` — descending, nulls last, then `security_id` | `score` |
| `offset` | integer ≥ 0 | 0 |
| `limit` | 1–100 | 50 |

Anything else is 400 naming the parameter. Response (values illustrative):

```json
{
  "state": "ready", "latest": true,
  "run": {"id": 7, "as_of": "2026-09-13", "started_at": "…", "finished_at": "…",
          "git_sha": "6b1c111", "config_hash": "9f3a71c2", "weight_version": "v2",
          "cutoff_offset_seconds": 108000, "logic": "v2 momentum, valuation, quality: …",
          "emits_alerts": false},
  "previous_as_of": "2026-09-12",
  "tiles": {"scored": 1499, "active_now": 1504, "partial": 41, "agreement_3": 58,
            "market_ranked_values": 15},
  "sectors": [{"code": "technology", "name": "Technology"}, {"code": "unclassified", "name": "Unclassified"}],
  "total": 1499,
  "rows": [{
    "symbol": "GEF", "name": "Greif", "sector": {"code": "consumer-cyclical", "name": "Consumer Cyclical"},
    "score": "84.8", "delta": null,
    "pillars": {"V": null, "Q": {"score": "79.0", "coverage": "0.75"}, "M": {"score": "91.0", "coverage": "1"}},
    "agreement": 2, "min_coverage": "0", "partial": true,
    "closes": [["2026-08-01", "41.20"], "…30 entries…"]
  }]
}
```

**Sector** is the level-1 `sector_node` reached from the security's `security_sector` row valid at the
run's `as_of`, walking `parent_id` as `peers.resolve` does, in the scheme of the level-0 peer group. It
is *not* the metric's `peer_group_id`, which can be the market. A security with no such row is
`unclassified`. `sectors` lists sectors with at least one row on the run.

**Δ** is `score − previous score` on the D7 previous night, null when there is no previous night or the
security was not scored on it. **`partial`** is `min_coverage < 1`.

**Tiles:** `scored` — snapshots on the run; `active_now` — `security.is_active` today, labelled "active
now"; `partial`; `agreement_3`; `market_ranked_values` — `metric_daily` rows on the run with
`fallback_level = 0` whose security has a `security_sector` row valid at `as_of`, labelled "metric values
ranked against the market" (a thin peer bucket, not an unclassified security).

**Closes** for display are read with `trade_date <= as_of` and **no `observed_at` bound**, then adjusted
with `screener.scoring.adjusted_closes` (D11).

**D10 — `GET /api/screen/security?symbol=&run=`.** The symbol is matched case-insensitively against
current `security_symbol` rows with a leading `$` stripped. None → 404. More than one security → 409
`ambiguous_symbol` listing their exchanges. Found but no snapshot on the run → `{"scored": false,
"symbol", "name", "sector", "active", "closes"}`. Otherwise (values illustrative):

```json
{
  "scored": true, "run_id": 7, "latest": true,
  "symbol": "JPM", "name": "JPMorgan Chase",
  "sector": {"code": "financial-services", "name": "Financial Services"},
  "industry": {"code": "banks-diversified", "name": "Banks - Diversified"},
  "score": "71.2", "partial": false,
  "pillars": [{
    "code": "valuation", "key": "V", "score": "44.5", "present": 2, "expected": 2,
    "metrics": [{
      "code": "earnings_yield", "name": "Earnings yield", "unit": "percent", "higher_is_better": true,
      "status": "ok",
      "stored": {"raw": "0.0741", "percentile": "58.0", "peer_group": "Financial Services",
                 "peer_count": 238, "market_ranked": false, "period_basis": "TTM", "period_end": "2025-12-31"},
      "reproduced": "0.0741",
      "reason": null
    }]
  }],
  "reproduction": {"visible_through": "…", "run_build": "6b1c111", "running_build": "6b1c111",
                   "refreshed_inputs": []},
  "closes": [["2026-06-18", "272.10"], "…60 entries…"]

```

Pillars are ordered Valuation, Quality, Momentum. `expected` comes from `ratios.applicable(industry)`
for Valuation and Quality and from the four momentum codes for Momentum. A pillar with no score has
`score: null` and still lists its metrics.

**D11 — Display prices ignore the cutoff; reproduction does not.** Display closes (D9, D10, D17) are
the currently stored bars, adjusted with `adjusted_closes`; reading them under a run's cutoff would drop
the last week after every ingest (F13). The adjustment's own per-bar split rule already handles bars
restated after a split. It inherits the split rule's documented calendar-boundary gap (scoring spec D4
erratum); the chart claims no more than that rule does.

### Traceability

**D12 — An explaining form of the scoring functions.** `basis.market_cap`, every Valuation and Quality
formula in `ratios.py`, `basis.index_facts` and `metrics.compute` gain an explaining form that returns,
per metric, either the value or `Absent(reason)`. The existing functions become thin filters over it
with unchanged signatures. When several conditions would each make a metric absent, **the first one in
the formula's evaluation order is reported.** Reasons come from fixed templates:

- **market cap:** `no market cap: no close visible` · `latest close is <n> days old` ·
  `split on <date>` · `no share count within 15 months` · `market cap ≤ 0`
- **currency:** `facts reported in <currencies>, not <currency>` — when `index_facts` dropped facts an
  input needed
- **period basis:** `no clean TTM or annual figure for <inputs>`
- **balance at a basis date:** `no <item> at <date>` (`roic`, `roe`)
- **newest balance:** `no date within 15 months holding all of <items>` (`ebitda_ev`, `book_yield`,
  `debt_to_equity`)
- **D5 rules:** `equity ≤ 0` · `enterprise value ≤ 0` · `invested capital ≤ 0` ·
  `interest expense ≤ 0` · `D&A negative` · `capex positive` · `revenue ≤ 0`
- **momentum:** `no visible bars` · `price history shorter than the <n>-month window` ·
  `a past close ≤ 0` · `52-week high ≤ 0`

**This is the one change to scoring, and it must not change what scoring writes.** The guard is not a
test comparing the two forms — a filter over the explaining form would pass that by construction — but
(a) every existing scoring test passing without edits (`test_scoring_ratios.py`,
`test_scoring_basis.py`, `test_scoring_metrics.py`, `test_scoring_run.py`, `test_scoring_run_ratios.py`),
and (b) a golden test: `score()` over a fixed multi-sector fixture, with its full `metric_daily`,
`pillar_score_daily` and `snapshot_daily` output captured **before** the refactor and asserted equal
after.

**D13 — Reproduction sees what the run saw.** For one security, `explain.py` reads facts, bars and
actions visible through `least(run cutoff, run.started_at)` — the run's actual view (F14) — plus the
security's currency and its industry at `as_of`, and calls the explaining forms. It then checks whether
that security's inputs **changed after the run started**:

- bars with `trade_date` in the momentum window and `observed_at > started_at` → *price inputs refreshed*
- facts with `observed_at > started_at` → *fundamental inputs refreshed*

`refreshed_inputs` lists which. A metric depending on refreshed inputs — momentum on price; every
Valuation ratio on price (through market cap) and facts; Quality on facts — is not compared (D14).

**D14 — Every applicable metric gets exactly one status.**

| status | stored row | reproduction | panel |
|---|---|---|---|
| `ok` | yes | equal to stored `raw_value` | normal row |
| `mismatch` | yes | different value, or absent | both values and the difference; "does not reproduce" |
| `absent` | no | absent | "—" and the reason |
| `unexpected` | no | a value | "not scored, but reproduces now" and the value |
| `refreshed` | either | not compared | stored row, or "—"; "inputs changed since this run" |
| `unchecked` | either | reproduction failed | stored row, or "—"; "could not re-check" |

Known causes of `mismatch` and `unexpected`, shown as a note when either appears: a build difference
(`run_build` ≠ `running_build`); a currency change or sector reclassification since the run (F15, not
point-in-time in scoring's own reads); the split rule's calendar-boundary gap. Percentiles are **not**
re-derived — they depend on every peer — so `ok` means the raw value reproduces, and the panel says so.

### States and Steven

**D15 — The Overview page.**

- **Header:** "Screen for <as_of>", finished time, weight version; **footer:** short git SHA and config
  hash. Banner removed.
- **Filters:** Sector, Pillar agreement ≥, Partial (all / only / hide), Sort; each change fetches page one
  of the pinned run; paging shows "1–50 of 1,499".
- **Tiles:** Scored (`1,499 / 1,504 active now`), Partial scores, All three pillars top-quartile, Metric
  values ranked against the market.
- **Table:** Security, Sector, Score (◐ when partial), Δ 1d ("new" when null), V, Q, M ("—" when absent),
  Agree (of 3), 30-day sparkline.
- **Chart:** "<SYM> — adjusted close, 60 trading days", through the one renderer's price mode (D16).
- **States:** awaiting first night → one card, no table; a newer night → a banner with refresh; unscored
  security → the panel says "not scored on <as_of>"; request failure → an inline error, never stale
  rows.

**D16 — The one renderer gains a price mode.** `ChartSpec` gains `kind: "score" | "price"`; `median` and
`threshold` become optional and are only drawn in score mode. Price mode uses a data-driven domain with
5% padding, three rounded ticks, D5 price precision for labels, and hover text "close <price> on <date>".
A spec with no `kind` is score mode, so threads already saved in browser storage — including ones with
`crossing` marks — still render. The dashboard's price chart uses this renderer too, so there is one way
to draw a chart across the page, the chat and Discord; the table's sparkline remains a bare polyline.

**D17 — Steven's chart.** `bot/tools/charts.py`:

- **Reads** in at most three `playground.select` calls — the security with its current snapshot and
  pillar scores on the screen's run; 60 bars with `observed_at`; corporate actions — parsed through
  `screener.screen.rows`, adjusted with `adjusted_closes`.
- **Matches** a symbol as D10 does; names are no longer matched. Unknown → "<X> is not a current symbol
  in the universe"; inactive → "<X> is no longer in the universe".
- **Marks** `peak`, `low`, `surge`, `drop`, `latest` from the series; labels use D5 price precision and
  surges and drops are percent moves over their run of days.
- **Caption:** blended score, V/Q/M and "partial" on the screen's run; "not yet scored" when no v2 run
  exists (prices are still drawn — D11 needs no run); "not scored on <as_of>" for an unscored security.
- **Playground unavailable** (`NotConfigured`/`Unavailable`): the tool says the chart is unavailable
  because the database cannot be reached. Before this, the chart worked without a database; after it,
  it cannot, and that is the point.
- **Prompt:** the tool description says "60-day adjusted price", and `agent.py`'s chart paragraph drops
  "a crossing" and the illustrative-data line, saying figures are real adjusted closes and scores come
  from the latest scored night.

**D18 — The palette publishes real context.** The Overview publishes a summary built from the selected
real row, most important first so the 400-character cut in `describe()` loses only the tail: symbol and
name, score and partial status, Δ or "new", V/Q/M, agreement of 3, sector, active filters. The
`illustrative` field and its note are deleted from `screen-context.tsx` rather than set to false, since
nothing will be illustrative. The Steven page notice is removed.

## 4. Conventions this follows

- Each package has a small public surface through `__init__.py`; nothing outside imports a submodule.
- SQL is literal with bound parameters; `sort` selects one of five fixed `order by` literals.
- Pure computation separated from reads: `rows`, `shape` and the explaining forms are pure.
- Behind the session unconditionally.
- A missing value is absent, never imputed; on screen "—", with a reason where there is one.
- One chart renderer (`web/lib/chart-svg.ts`) for the page, the chat and Discord.
- Money and ratios travel as decimal strings, never floats.

## 6. A request

1. The page calls `/api/screen` with its filters and, after the first response, the pinned `run`.
2. The handler checks the session, resolves the run (D7/D8), reads tiles, sectors and one page of rows
   with the previous night's scores, reads display bars and actions for those rows (D11), and shapes the
   response through typed rows.
3. Selecting a row calls `/api/screen/security` with the same `run`: stored pillars and metrics, then
   `explain` reproduces every applicable metric under the run's view and assigns each a status (D13/D14).
4. The chart and panel render; the palette summary is published from the same row.

---

## 7. Failure behaviour

- **No session:** 401. **Database unreachable:** 503 with the reason.
- **Bad parameter:** 400 naming it. **Pinned run gone or not qualifying:** 409 `run_changed`.
- **Unknown symbol:** 404. **Ambiguous symbol:** 409 `ambiguous_symbol`. **Not scored:** `scored: false`.
- **Reproduction raises:** stored metrics returned; every metric `unchecked`; logged with security and
  run.
- **Steven with the playground unavailable:** says so; no chart.
- **The page never falls back to concept data** — it no longer exists.

## 8. Testing

**Piece (a).** Every existing scoring test passes unedited. The golden test captures `metric_daily`,
`pillar_score_daily` and `snapshot_daily` for a fixture covering a standard company, a bank, a REIT, a
thin bucket, a split, a stale close, negative equity and a foreign-currency fact — captured from the
code before the refactor and committed. One test per D12 reason template, including the currency reason
and the first-reason-wins rule.

**Piece (b).**

- *Pure:* `rows` parses both a native row and a `playground.Result` row into the same record; `shape`
  computes Δ and null, partial, D5 decimal strings, and adjusts closes across a split fetched before its
  bar.
- *Database:* only v1 runs → awaiting; a failed v2 run ignored; latest ok v2 run chosen; Δ against the
  previous v2 night, null across a weight-version change and for a newly scored security; pinned run
  served with `latest: false` after a newer run lands, and 409 for an unknown id; every filter and sort,
  ties broken by `security_id` with no overlap between consecutive pages; sector as the level-1 node at
  `as_of`, `unclassified`; each tile; display closes include a bar re-stamped after the cutoff.
- *Detail:* standard and bank `expected`; `ok`; `mismatch` from a fixture `raw_value` altered after the
  run; `absent` with its reason; `unexpected` from `security.currency` changed after the run, so facts
  the run dropped as foreign now count and a ratio reproduces (F15); `refreshed` from a bar re-stamped
  after `started_at` (momentum and Valuation refreshed, Quality still compared) and from a fact
  re-stamped after `started_at`; `unchecked`
