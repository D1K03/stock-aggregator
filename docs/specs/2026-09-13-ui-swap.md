# UI swap: real scores on the dashboard and in Steven's charts

Status: specified 2026-09-13.

The dashboard and Steven's `chart` tool have drawn invented, schema-shaped data since before ingest
existed, and every surface said so. Scoring now writes real v2 snapshots — Momentum, Valuation and
Quality — so this replaces the fiction with the real screen, and makes the project's hard constraint
visible where a person looks: **every score traces back to visible raw inputs**, one click from the
row. Standing decisions live in `DESIGN.md`; the tables read are specified in
`docs/specs/2026-09-05-scoring.md` and `docs/specs/2026-09-13-ratios.md`.

Scope: **two read endpoints, a shared read module, the Overview page, the traceability panel, Steven's
chart tool, and the deletion of `screener.concept` and `web/lib/data.ts`.** Nothing is ingested,
nothing new is scored, no schema changes, and no alert is evaluated.

---

## 1. What this has to satisfy

1. **Nothing on screen is invented.** A figure either comes from a table or is not drawn. Features
   that have no data yet are absent rather than mocked.
2. **Every score traces to its inputs on the page.** Selecting a security shows each metric's raw
   value, percentile, peer group and count, and the period it was computed on; a metric that applies
   but could not be computed says why.
3. **A partial score cannot pass for a complete one.** The real screen has partial scores near the top
   (§2 F9).
4. **The screen and Steven cannot disagree.** One definition of "the screen", read by both.
5. **Honest about time.** v2 history begins with its first production night; v1 nights are not
   comparable and are known to carry distorted momentum.

---

## 2. Findings

**F1 — what the concept UI draws.** The Overview is a client component that imports twelve invented
rows from `web/lib/data.ts` at build time: a header ("run #412 … weights v3-momentum-heavy"), four
stat tiles, a table (score, Δ1d, five pillars V/Q/M/S/I, agreement, flags, 30-day sparkline), a
"blended score, 60d" chart built from a seeded random walk, an alert feed, a footer with provenance,
and a banner saying ingest does not exist. `screener.concept` mirrors the same rows in Python for
Steven's `chart` tool, and `tests/test_charts.py` parses the TypeScript to keep the copies aligned.

**F2 — a third of it has no data behind it.** Sentiment and Insider pillars, event flags, alerts and
threshold crossings describe systems that do not exist.

**F3 — there is no data path.** The page has never fetched a score. Other pages read through the
status service behind the GitHub session (`/api/audit`, `/api/skybird`, `/api/playground`); the web
container holds no database credentials.

**F4 — the real screen is ~1,500 rows, not twelve.** A 30-close sparkline on every row of every
response is ~45,000 points per page load.

**F5 — score history is days old.** v2's first production night is 2026-09-13. The four v1 nights
(09-09 to 09-12) scored Momentum alone and carry split-distorted momentum (scoring spec D4 erratum),
so they cannot share a line with v2.

**F6 — the fiction is load-bearing in three more places.** Steven's system prompt says the chart
tool's figures are illustrative sample data (`src/screener/bot/agent.py`); the Overview publishes
`illustrative = true` into the command palette's context (`web/lib/screen-context.tsx`), which tells
the model the same; and the Steven page carries a notice. Left alone, each would describe real scores
as fake.

**F7 — nothing records why a metric is absent.** `metric_daily` holds only metrics that were computed.
An applicable metric that could not be computed leaves no row.

**F8 — the web app has no test runner.** Only `eslint`. CI builds the web image, so TypeScript errors
fail CI, but behaviour on the page is unverified by any automated test.

**F9 — partial scores rank high.** On a copy of production scored under v2 with the split fix, GEF
ranked fifth with `min_coverage = 0` — a whole pillar absent, blended over the two present.

**F10 — Steven's read-only role can read everything needed.** `playground_bot` holds `select` on
`security`, `security_symbol`, `security_sector`, `sector_node`, `peer_group`, `scoring_run`,
`scoring_logic_version`, `weight_version`, `snapshot_daily`, `pillar_score_daily`, `metric_daily`,
`metric`, `pillar`, `price_daily` and `corporate_action` (migration 017).

## 3. Decisions

**D1 — Swap plus traceability, and the concept is deleted.** The Overview and Steven's chart move to
real data in one cycle, and a traceability panel is added. `src/screener/concept/`,
`web/lib/data.ts`, `web/components/AlertFeed.tsx` and the drift test are deleted: a second copy of
invented data kept alive by a test is only justified while something draws it.

**D2 — Price now, score later.** The chart, the sparkline and Steven's tool draw **adjusted closes**:
60 trading days for the chart and Steven, 30 for the sparkline. A score-history chart is a later
cycle, once v2 has history worth drawing (F5). Steven's marks become `peak`, `low`, `surge`, `drop`,
`latest`; `crossing` is removed until score history and alerting exist.

**D3 — Remove until built.** The S and I pillar columns, the flags column, the alert feed and the
threshold-crossings tile are removed. Each returns with the cycle that builds its data. The freed
right column holds the traceability panel.

**D4 — Read endpoints on the status service, paged on the server, over one shared module.**
`GET /api/screen` and `GET /api/screen/security` live in `screener.health.server` behind the session,
as `/api/audit` does, using the application's own connection because the SQL is fixed and no user
input reaches it beyond bound parameters. Filtering, sorting and paging happen in SQL (F4). The SQL
and the row shaping live in a new package `screener.screen`, which the status service runs on its
connection and Steven runs through `playground.select` on his read-only role (F10) — one definition of
the screen for both surfaces.

Rejected: returning the whole screen and filtering in the browser (two calls per view and a client that
must know which rows are visible); a nightly JSON artifact (a second definition of the screen that can
drift from the tables); database credentials in the web container; building the screen from
browser-side SQL through the playground API (500-row cap, schema knowledge in TypeScript).

**D5 — Which night is the screen.** The latest `scoring_run` with `status = 'live'`,
`outcome = 'ok'` and `logic_version_id` equal to the version `screener.scoring.run.LOGIC_DESCRIPTION`
selects. The *previous* night for Δ is the latest such run with an earlier `as_of`. Runs on another
logic version are never shown or compared. With no qualifying run, both endpoints return
`{"state": "awaiting_first_night", "next_trigger_utc": "<ISO time>"}`, computed with
`screener.nightly`'s schedule arithmetic.

**D6 — `GET /api/screen`.** Query parameters, all optional:

| parameter | values | default |
|---|---|---|
| `sector` | a level-1 sector code | all |
| `agree` | `1`, `2`, `3` — minimum pillar agreement | none |
| `partial` | `only`, `hide` | both |
| `sort` | `score`, `delta`, `V`, `Q`, `M` (descending; nulls last) | `score` |
| `offset` | integer ≥ 0 | 0 |
| `limit` | 1–100 | 50 |

Response (`state: "ready"`; values illustrative):

```json
{
  "state": "ready",
  "run": {"id": 7, "as_of": "2026-09-13", "finished_at": "…", "git_sha": "6b1c111",
          "config_hash": "9f3a71c2", "weight_version": "v2", "cutoff_offset": "1 day 06:00:00",
          "logic": "v2 momentum, valuation, quality: …", "emits_alerts": false},
  "previous_as_of": "2026-09-12 | null",
  "tiles": {"scored": 1499, "active": 1504, "partial": 41, "agreement_3": 58, "market_fallback_metrics": 15},
  "sectors": [{"code": "technology", "name": "Technology"}],
  "total": 1499,
  "rows": [{
    "symbol": "GEF", "name": "Greif", "sector": "Consumer Cyclical",
    "score": 84.8, "delta": null,
    "pillars": {"V": null, "Q": {"score": 79.0, "coverage": 0.75}, "M": {"score": 91.0, "coverage": 1.0}},
    "agreement": 2, "min_coverage": 0.0, "partial": true,
    "closes": [["2026-08-01", 41.2], "…30 entries…"]
  }]
}
```

`delta` is `score − previous score` for the same security on the previous night, or null when there is
no previous night or the security was not scored on it; the page renders null as "new". `partial` is
`min_coverage < 1`. `market_fallback_metrics` counts `metric_daily` rows at `fallback_level = 0` for
securities that are classified (a thin bucket, not an unclassified security). Scores are rounded to one
decimal and closes to two in the payload only.

**D7 — `GET /api/screen/security?symbol=`.** 404 when the symbol is not current in
`security_symbol`. When it exists but has no snapshot on the screen's night, `{"scored": false, …}` with
its identity and closes. Otherwise:

```json
{
  "scored": true, "symbol": "JPM", "name": "JPMorgan Chase", "sector": "Financial Services",
  "industry": "Banks - Diversified", "score": 71.2, "partial": false,
  "pillars": [{
    "code": "valuation", "key": "V", "score": 44.5, "present": 2, "expected": 2,
    "metrics": [{
      "code": "earnings_yield", "name": "Earnings yield", "higher_is_better": true,
      "status": "ok | absent | mismatch | refreshed",
      "raw": 0.074, "percentile": 58.0,
      "peer_group": "Financial Services", "peer_count": 238, "market_fallback": false,
      "period_basis": "TTM | A | null", "period_end": "2025-12-31 | null",
      "reproduced": 0.074, "reason": null
    }]
  }],
  "reasons_build": {"run": "6b1c111", "running": "6b1c111"},
  "closes": [["2026-06-18", 272.1], "…60 entries…"]
}
```

Pillars are listed in the order Valuation, Quality, Momentum, with `expected` from
`ratios.applicable(industry)` for Valuation and Quality and the four momentum codes for Momentum. A
pillar with no score has `score: null` and still lists its metrics, all absent with reasons.

**D8 — Prices are adjusted by scoring's own function.** Closes come from `price_daily` with
`observed_at` and from `corporate_action`, under the screen's run cutoff, through
`screener.scoring.adjusted_closes`. The chart then cannot disagree with the returns momentum computed,
and a split can never draw as a crash.

**D9 — Absence reasons are reproduced on demand.** The detail endpoint re-reads that one security's
facts, bars, actions, currency and industry under the run's `as_of` and `cutoff_offset`, and calls the
scoring functions in an **explaining form**: each Valuation/Quality formula returns either a `Ratio` or
an `Absent(reason)`, and `basis.market_cap` reports why market cap is absent. Reasons are short
sentences built from fixed templates:

- `no market cap: no close visible` / `latest close is N days old` / `split on YYYY-MM-DD` /
  `no share count within 15 months`
- `no clean TTM or annual figure for <inputs>`
- `equity ≤ 0`, `enterprise value ≤ 0`, `invested capital ≤ 0`, `interest expense ≤ 0`,
  `D&A negative`, `capex positive`, `revenue ≤ 0`
- `no <item> at <date>` for a balance item missing at the basis date
- momentum: `price history shorter than the <n>-month window`

`compute_ratios` keeps its signature and becomes a filter over the explaining form, so **scoring's
output cannot change**; a test pins that the two agree. Reasons are not stored (F7): reproduction is
the traceability mechanism the ratios spec already chose (D14 there).

**D10 — The panel checks that the stored numbers reproduce.** For every metric the run computed, the
reproduced value is compared with the stored `raw_value`. Equal → `status: "ok"`; different →
`status: "mismatch"` with both values shown, labelled "does not reproduce". When the run's `git_sha`
differs from the running build, `reasons_build` shows both and the panel says reasons came from a newer
build — a mismatch is then expected rather than alarming. A failure inside reproduction never blocks
the panel: stored metrics render, reasons read "unavailable".

**Price bars are not append-only, so reproduction knows when it cannot be exact.** Facts are append-only,
but ingest's settling window rewrites the last seven days of `price_daily` with a new `observed_at`
(price-ingest D5). After the next night's ingest and before its scoring finishes — about twenty minutes
a night — the screen's run is still the latest, but some of its bars now sit past its cutoff, and
momentum and market cap would not reproduce. So before comparing, `explain` counts that security's bars
with `trade_date <= as_of` and `observed_at > cutoff`. When there are any, price-derived metrics
(momentum, and every Valuation ratio through market cap) get `status: "refreshed"` and the label "price
bars refreshed since this run" instead of `mismatch`; fundamentals-only metrics are still compared.

**D11 — Layout A, panel grid B.** The table fills the left; the right column holds the price chart
above the "Why this score" panel. The panel is a compact grid per pillar — metric (↓ when lower is
better), raw value, percentile bar, peers, period — with absent metrics listed as "—" and their reason,
a market-level fallback marked with its peer count, and an annual basis labelled "A".

**D12 — The Overview page.**

- **Header:** "Screen for <as_of>", finished time, weight version and cutoff from `run`. **Footer:**
  short git SHA and config hash. The Concept banner is removed.
- **Filters:** Sector, Pillar agreement ≥, Partial scores (all / only / hide), Sort. Changing one fetches
  page one; paging shows "1–50 of 1,499" with previous/next.
- **Tiles:** Scored (`1,499 / 1,504 active`), Partial scores, All three pillars top-quartile, Ranked
  against the market.
- **Table:** Security (symbol and name), Sector, Score (◐ when partial), Δ 1d ("new" when null), V, Q,
  M ("—" for an absent pillar), Agree (of 3), 30-day sparkline.
- **Chart:** "<SYM> — adjusted close, 60 trading days"; hover labels are dates from the data.
- **States:** awaiting first night → one card saying when it scores, no table; unscored security → the
  panel says so; request failure → an inline error, never stale rows.

**D13 — Steven's chart.** `bot/tools/charts.py` reads the screen's run, the security's snapshot and
pillar scores, and 60 bars with actions through `screener.screen`'s SQL on `playground.select`, adjusts
them with `adjusted_closes`, and places marks from the series as before. The caption carries the
blended score, V/Q/M, and "partial" when it applies; the tool result sentence no longer says
"illustrative". An unknown ticker is answered with "not in the universe", not a list of symbols. The
system prompt line describing chart figures as illustrative sample data is replaced with one saying they
are real adjusted closes and that scores come from the latest scored night.

**D14 — The palette publishes real context.** The Overview calls `usePublishScreen` with
`illustrative = false` and a summary built from the selected real row: symbol and name, sector,
blended score, Δ or "new", V/Q/M with "absent" where so, agreement of 3, partial status, and the active
filters. The Steven page's notice about illustrative charts is removed. Comments elsewhere that contrast
a page with "the concept data" are corrected.

## 4. Conventions this follows

- Each package has a small public surface through `__init__.py`; nothing outside imports a submodule.
- SQL is literal with bound parameters (psycopg `LiteralString`); `sort` maps to one of five fixed
  `order by` literals, never to interpolated text.
- Pure computation separated from reads: `screen.shape` and the explaining form are pure.
- Behind the session unconditionally, never `config.enabled and login is None`.
- A missing value is absent, never imputed, and on screen it is "—" with a reason where one exists.
- One renderer for Steven's charts (`web/lib/chart-svg.ts`), unchanged.

## 6. A request

1. The page loads, reads filters from state, and calls `/api/screen`.
2. The handler checks the session, opens a connection, finds the screen's run (D5), and returns
   `awaiting_first_night` if there is none.
3. It reads the tiles and sector list, one page of rows with pillars and the previous night's score,
   and, for those rows only, bars and actions under the run's cutoff; `shape` adjusts closes and builds
   the response.
4. Selecting a row calls `/api/screen/security`: stored pillars and metrics for that security, then
   `explain` reproduces every applicable metric and pairs each with its stored row.
5. The panel and chart render; the palette summary is published from the same row.

---

## 7. Failure behaviour

- **No session:** 401. **Database unreachable:** 503 with the reason, as `/api/audit`.
- **Unknown symbol:** 404. **Not scored on the screen's night:** 200 with `scored: false`.
- **Bad parameter** (unknown `sort`, `limit` out of range, non-integer offset): 400 naming it.
- **Reproduction raises:** stored metrics still returned; every metric's `reason` is `"unavailable"`
  and `status` stays `ok` or `absent` from the stored data alone; logged with the security and run.
- **The page never falls back to concept data** — it no longer exists to fall back to.

## 8. Testing

**Pure.**

- Explaining form: one test per absence reason in D9; and for every ratio fixture in
  `tests/test_scoring_ratios.py`, `compute_ratios` equals the `Ratio` half of the explaining form.
- `market_cap` explanations: no close, stale close, split window, no share count.
- `shape`: delta and null, partial, rounding confined to the payload, closes adjusted across a split
  fetched before its bar.

**Database** (`tests/test_screen.py`).

- Only v1 runs → `awaiting_first_night`; a failed v2 run is ignored; the latest ok v2 run is chosen;
  Δ against the previous v2 night, null for a security new on this one.
- Filters: sector, `agree`, `partial=only` and `hide`; sort by each key with nulls last; `offset`,
  `limit`, `total`; tile counts on a fixture with a thin bucket and a partial security.
- Detail: pillar `expected` counts for a standard company and a bank; an applicable absent metric listed
  with its reason; a computed metric whose reproduction equals the stored value → `ok`; the same row
  with `raw_value` altered in the fixture → `mismatch`; a bar in the momentum window re-stamped with an
  `observed_at` past the run's cutoff → momentum and Valuation `refreshed`, Quality still compared; unknown
  symbol → none; unscored → `scored: false`.

**Handlers** (following `tests/test_health.py`): 401 without a session, 404, 400 on a bad `sort`, 503
with the database unreachable, and the D6/D7 top-level keys.

**Steven.** Mark placement on a fixed series; the tool against database fixtures through the read-only
role, returning a caption with the real score and "partial"; the system prompt contains no
"illustrative"; `crossing` is no longer an accepted mark.

**Web.** `eslint` and `next build` pass (CI builds the web image).

**In a real browser, before merge.** Run the local stack on a copy of production's `public` schema that
includes a v2 night, sign in through `/auth/local`, and check: real provenance in the header and footer;
each filter and sort; paging; the panel for a partial security, a bank and a recent splitter (its chart
continuous across the split); a deliberately absent metric's reason; Steven's chart for one security.
Screenshots go in the pull request.

## 9. Out of scope

- **A score-history chart**, per D2.
- **Alerting, crossings, event flags, Sentiment and Insider**, per D3.
- **Any change to what scoring computes or writes**, per D9.
- **Structured multi-series palette context** (`PLAN.md` lists it); the summary stays prose.
- **Export, watchlists, comparison of two securities.**
- **A second chart renderer.** The dashboard's `ScoreChart` keeps its own SVG as today; unifying it with
  `web/lib/chart-svg.ts` is its own change.

## 10. Open parameters

- **Page size 50, maximum 100**; **30 closes** for sparklines, **60** for the chart and Steven.
- **Tile definitions**, especially "ranked against the market", which counts metric rows rather than
  securities.
- **Sort keys** — five for now; percentile columns inside the panel are not sortable.
- **Reason wording** — templates in D9; the codes behind them are what tests pin.
